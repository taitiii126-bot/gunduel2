# GUN DUEL サーバー

`index.html`（ゲーム本体）のオンライン対戦用サーバーです。Node.js だけで動きます（npm パッケージ不要）。

## 全体の構成

```text
ゲームのページ   GitHub Pages   https://あなたのユーザー名.github.io/gunduel/
対戦サーバー     Railway        wss://〇〇.up.railway.app（地域：Singapore）
ログイン         Discord        （サーバーがDiscordと直接やり取りする）
```

ページを開くときだけ GitHub Pages からファイルを受け取り、**対戦中は Railway のサーバーとだけ通信**します。設定はすべてブラウザで完結します。

---

## 1. GitHub にアップして、ゲームを公開する

1. github.com の右上「＋」→ **New repository** → 名前を `gunduel`、**Public** で作成
2. 「uploading an existing file」を開き、パソコンの `Downloads\GUNDUEL` フォルダの**中身**（`index.html`・`sim.js`・`lang.js` と `server` フォルダ）をドラッグ → **Commit changes**
3. リポジトリの **Settings → Pages** で、Branch を `main`、フォルダを `/ (root)` にして Save

1〜2分で `https://あなたのユーザー名.github.io/gunduel/` でゲームが開けるようになります。公開リポジトリで問題ありません（秘密の情報はファイルに入っておらず、Railwayの設定にだけ置きます）。

## 2. Railway にサーバーを載せる

### サービスを作る（または今のサービスを差し替える）

- **今のサービス（gun-duel-server）を使う場合**：サービスを開き **Settings → Source** で「Connect Repo」から `gunduel` リポジトリを選びます。アドレスが今と同じまま使えます
- **新しく作る場合**：プロジェクトで **＋ New → GitHub Repo** → `gunduel` を選びます

### Settings で設定する項目

| 項目 | 設定 |
|---|---|
| Source → **Root Directory** | `server` |
| Deploy → **Region** | **Southeast Asia (Singapore)** |
| Deploy → Healthcheck Path（任意） | `/health` |
| Networking → **Public Networking** | 「Generate Domain」でアドレスを作る（すでにあればそのまま） |

起動コマンドは自動で `npm start`（= `node server.js`）になります。ポートもRailwayが自動で渡します。

### Variables（環境変数）

| 変数 | 値 |
|---|---|
| `TRUST_PROXY` | `1` |
| `DATA_DIR` | `/data` |
| `DISCORD_CLIENT_ID` | DiscordのClient ID（3.で取得） |
| `DISCORD_CLIENT_SECRET` | DiscordのClient Secret（3.で取得） |
| `ALLOWED_ORIGINS` | `https://あなたのユーザー名.github.io`（パスは付けない） |

### Volume（アカウントの保存先）

サービスを右クリック（またはコマンドパレット）→ **Add Volume** → Mount Path を **`/data`** にします。これがないと、再デプロイのたびにアカウントと戦績が消えます。

### 動作確認

ブラウザで `https://〇〇.up.railway.app/health` を開きます。

- `{"ok":true,...}` と出れば起動しています
- **`yourIp` があなたの本当のIPになっているか**確認してください（`10.` や `100.` で始まる場合は、IPごとの制限が正しく働かないので教えてください）

## 3. Discord ログインを有効にする

1. https://discord.com/developers/applications でアプリを作る（New Application）
2. **OAuth2** で **Client ID** をコピーし、**Reset Secret** で **Client Secret** を作ってコピー（一度しか表示されません）
3. 同じ画面の **Redirects** に `https://あなたのユーザー名.github.io/gunduel/` を追加して **Save Changes**（末尾の `/` まで完全一致）
4. RailwayのVariablesに2つの値を入れる（入れると自動で再起動します）

`https://〇〇.up.railway.app/api/config` が `{"login":true,...}` を返せばOKです。**シークレットはGitHubやHTMLには絶対に置かないでください。**

## 3.5 ティア昇格をDiscordに投稿する（任意）

ログイン中の人がティアを上げると、Discordのチャンネルに「〇〇が HT3 に昇格しました！」と投稿されます。

1. Discordで投稿したいサーバーを開き、**サーバー設定 → 連携サービス → ウェブフック → 新しいウェブフック**
2. 名前（例：GUN DUEL）と投稿先のチャンネルを選び、「**ウェブフックURLをコピー**」
3. RailwayのVariablesに次の2つを入れる

| 変数 | 値 |
|---|---|
| `DISCORD_WEBHOOK_URL` | コピーしたウェブフックURL（**人に見せない**。知られると誰でもそのチャンネルに投稿できます） |
| `GAME_URL` | `https://あなたのユーザー名.github.io/gunduel2/`（投稿のタイトルがゲームへのリンクになる） |

ティアはレート（サーバーが計算）で決まりますが、最初のレートだけはCPU戦の到達度（自己申告）から作られます。そのため次の制限を付けています。

- ログイン中の本人だけが報告できる
- 前に報告したティアより上のときだけ投稿（1人最大10回）
- 同じ人は20秒に1回まで、全体でも1分に10件まで
- メンションは名前の表示だけで通知は飛ばず、@everyone なども無効

## 3.6 Discord の /info コマンド（任意）

Discordで `/info ユーザー名` と打つと、そのプレイヤーのティア・勝率（勝ち/負け）・二つ名・ひとこと・オンライン状態が表示されます。
ログインに使っている**同じDiscordアプリ**をそのまま使います。ボットのトークンは要りません（サーバーが Client ID と Client Secret で自動的にコマンドを登録します）。

1. https://discord.com/developers/applications でログイン用のアプリを開き、**General Information** の **PUBLIC KEY** をコピー（64文字の英数字）
2. Railway の Variables に `DISCORD_PUBLIC_KEY` として貼る → 自動で再起動し、ログに `discord: /info コマンドを登録しました` と出ればOK
3. 同じ **General Information** の **INTERACTIONS ENDPOINT URL** に `https://〇〇.up.railway.app/discord/interactions` を入れて **Save Changes**（保存したときにDiscordが接続を確認します。エラーになる場合は、2の再起動が終わってからもう一度）
4. Discordサーバーに追加する：ブラウザで次のアドレスを開き、追加したいサーバーを選んで「認証」（サーバーの管理権限が必要）
   `https://discord.com/oauth2/authorize?client_id=（Client ID）&scope=applications.commands`
5. Discordのチャンネルで `/info` と打ち、出てきた候補を選んで名前を入れる

- 探せるのは、**ゲーム内の名前・Discordの名前・フレンドID（8文字）・@メンション**。名前は一部だけでも、1人に決まれば見つかります
- 対象は、Discordでログインしたことのあるプレイヤーだけです（ゲストは記録がないため出ません）
- 見つからないとき・同じ名前が何人もいるとき（フレンドIDの一覧が出ます）は、コマンドを打った本人にだけ見えるメッセージで答えます
- Discordを英語で使っている人には英語で答えます
- PUBLIC KEY は秘密ではありませんが、Client Secret と同じく **GitHub や HTML には置かず**、Railway の Variables にだけ入れてください
- ボットをメンバー一覧に出したい場合だけ：アプリの **Bot** で「Reset Token」→ `DISCORD_BOT_TOKEN` に入れ、4 のアドレスの `scope` を `bot%20applications.commands` にして追加します（トークンは絶対に人に見せない）

## 4. ゲーム側の設定

ゲームのタイトル画面下の「SERVER」欄に `wss://〇〇.up.railway.app` を入れると、オンライン対戦とログインが使えます。全員に反映するには、`index.html` の `id="server-url"` の `value` を書き換えてGitHubに上げ直します（今のRailwayサービスを使うなら書き換え不要です）。

## 更新するとき

GitHubのWebでファイルを差し替えるだけです。Railwayが自動で再デプロイし、GitHub Pagesにも自動で反映されます。

## チート対策

### 自動で行われること

| 対策 | 内容 |
|---|---|
| サーバー権威 | 移動・弾・当たり判定・ダメージ・回復・リロードは全部サーバーが計算。HP改ざん・速度改ざん・連射ツールは効かない |
| 本人確認 | 名前はプロフィールで自由に決められるが、ログイン中の人は対戦相手に Discord の名前も表示される（なりすまし対策） |
| 自動射撃BOTの検知 | 「狙いが合った瞬間に撃つ」を人間には無理な精度で続けたら検知 |
| 自動回避の検知 | 自分を狙った弾が出てから0.1秒以内に跳んで避けるのを、人間には無理な割合で続けたら検知 |
| マクロの検知 | 左右・しゃがみの切り替えが1秒30回以上、3秒続いたら検知 |
| コンソール・ブックマークレット対策 | ゲームの中身（武器の数値・敵の位置・戦績の記録処理）を外から見えない形に閉じ込め、基本数値は書き換え不可。「拾ったコードを貼るだけ」のチートは動かない |
| 戦績の水増し防止 | 次の場合は記録しない：ゲストが混ざっている／同じアカウント同士／同じネットワーク同士（サブ垢対策）／どちらかが放置／疑わしい操作を検知／同じ2人の対戦が1日10回を超えた |
| 途中退出 | 1ラウンド以上終わったあとに抜けたら負けとして記録（負けを逃げられない） |
| PING偽装防止 | 相手に見せるPINGはサーバーが自分で測った値 |
| 荒らし対策 | 部屋番号の入力ミスは10分で10回まで／同じIPからの接続は16本まで／同じIPが同時に作れる部屋は3つまで／1接続あたりのメッセージ数制限 |

検知しても本人には知らせません（対策を調整されないため）。ログとアカウントに記録されるので、BANするかはあなたが判断します。

### 怪しい人を見つけて BAN する

1. Railwayのサービス → **Deployments → View Logs** で `SUSPECT` を検索
2. `SUSPECT discord=123456789 name=〇〇 ip=… 理由` の形で出ているので、`discord=` の数字をコピー
3. Variables の `BANNED_DISCORD_IDS` に入れる（複数ならカンマ区切り）

BANされた人はログインもできず、保存されていたログイン状態も使えなくなります。ゲストで荒らす人は `BANNED_IPS` にIPを入れます。

**BANを確実に効かせたい場合**は `REQUIRE_LOGIN=1` にしてください。オンライン対戦がDiscordログイン必須になり、ゲストでは入れなくなります。

### 注意

- **ブラウザの中で動くものは、原理的に100%は守れません。** デバッガを使いこなす人なら、CPU戦の改造やティア表示の偽装はできます。ただしオンライン対戦の勝敗と戦績はサーバーが決めるので、改造しても結果は変わりません

- **同じ家のWi-Fiから2人で遊ぶと、同じネットワーク扱いで戦績が記録されません。** 記録したい場合は `ALLOW_SAME_IP_RECORDS=1` にしてください（サブ垢での水増しは防げなくなります）
- ティア（LT/HT）は**レートで決まり、レートはサーバーだけが計算します**。ブラウザを改造しても、サーバーのレートは変わりません
- ただし**最初のレート**だけは、CPU戦の到達度（自己申告）から作ります。偽れば高いレートから始められますが、相手の強さは自分のレートに合わせて決まるので、実力が伴わなければすぐ下がります
- CPU戦の成績とティアの到達度は、ログイン中ならプロフィールと一緒にサーバーにも保存されます（別の端末でも同じになる）。ただし自己申告なので公式記録（オンライン戦績・レート）とは分けて扱います

## 仕組み

- 60Hzで計算して、60Hzで状態を配信します。ゲーム側は相手の位置を速度から先読みして表示するので、通信の遅れが見えにくくなっています
- ログインはDiscordのOAuth2。サーバーがDiscordと直接やり取りし、ゲームには自前のトークンだけを渡します
- **プロフィールの保存**：ログイン中は、名前・ひとこと・称号・見た目・背景・CPU戦の成績とティアを `users.json` に保存します。変えると1.5秒後に自動で送られ、別の端末で開くと同じプロフィールになります（2台で同時に変えた場合は、戦績は大きい方を残して合わせます）
- **フレンドID**：アカウントごとに英数字8桁（見間違えやすい 0/O・1/I/L は使わない）。プロフィール画面に表示され、あとから変わりません
- **オンライン状態**：ログイン中の人は、ページを開いている間サーバーとつながったままになります（対戦用とは別の1本）。状態は「オンライン／CPU対戦中／対戦中／オフライン（最後にいた時刻）」。`/health` の `online` が今オンラインの人数です
- **フレンド**：フレンドIDで申請し、相手が承認するとフレンドになります（お互いに申請した場合はそのままフレンド）。上限は100人、承認待ちは50件まで。一覧の「オンライン／CPU対戦中／対戦中／オフライン（〇分前）」は、状態が変わるとすぐに届きます
- **対戦の招待**：招待する人が部屋を作り、サーバーがその部屋番号をフレンドに届けます。受けた人の画面の上に通知が出て、10秒で自動的に閉じます（返事がないことも招待した人に伝わります）。CPU戦の途中なら、試合が終わってから表示されます。対戦中の人・オフラインの人は招待できません
- 荒らし対策として、フレンドの操作は1人1分30回、招待は1分12回、フレンドIDでの検索は1分60回までです
- **対戦のしかた**：ランダムマッチ（ランクマッチ／アンランクマッチ）・部屋番号・フレンド招待の3つ。
  - **ランクマッチ**：レートが動く。ログインが必要。近いレートの相手から探し、待つほど範囲が広がる（±50 → 15秒で±100 → 30秒で±200 → 45秒で±400 → 75秒で制限なし）
  - **アンランクマッチ**：レートは動かない。レート帯を問わず、すぐ組む
  - **相手が見つからないとき**：サーバーが相手役を1人作って対戦します。名前・見た目・称号・武器・戦績・通信の速さを持ち、対戦中の操作もサーバーが動かすので、ブラウザ側からは人のプレイヤーと同じに見えます
    - 強さはその人のレートとちょうど互角（`sim.js` の `aiForRate`）。BOT同士を実際に戦わせて「レート差200＝勝率76%」になるよう目盛りを測ってあります（`scratchpad/calib-bot.js`）
    - この相手に勝ってもレートは上がりますが、**LT1の下限（2250）で止まります**。HT1は本物のプレイヤーに勝った人だけ
  - **部屋番号・フレンド招待**：レートは動かない（気軽な対戦のため）
- **ランキング**：`GET /api/ranking` がレート順の上位（既定100位）と自分の順位を返します。サーバーで集計して既定5分ごとに作り直すので、人が増えても重くなりません。BOTはアカウントを持たないので載りません。返すのは名前・称号・ティア・レート・勝敗だけで、DiscordのユーザーIDは出しません
- **レート**：ランクマッチだけで動きます（CPU戦では動きません）。計算は `sim.js` の `rateChange` / `applyRate`、ティアの区切りは `TIER_MIN`。
  - 1000から始まり、Elo方式（勝てば上がり負ければ下がる。格上に勝つほど大きく上がる）
  - 格上に勝つとティア差ぶんのボーナス（最大+60）、連勝中は上がり方が速い（最大2倍）
  - 格下に連敗すると下がり幅が増える（2連敗1.2倍・3連敗1.5倍・4連敗以降1.7倍）。レートが高い帯ほど負けたときに大きく下がる
  - ティアはレートで決まる：（未ランク）〜999／LT5 1000／HT5 1100／LT4 1200／HT4 1350／LT3 1500／HT3 1650／LT2 1800／HT2 2000／LT1 2250／HT1 2550
  - 一度上がったティアは、下限より60下がるまで落ちない（降格の猶予）
- **称号（71種類）**：一覧は `sim.js` の `TITLES`、名前と取り方は `lang.js` の `title.〇〇` / `tcond.〇〇`。武器ごとの称号は全14武器 × とどめ10・50・100回（100回はすべてレア。取り方の文は `tcond.kill` のひな形）。レアの称号はカードで青いネオンに光ります。オンライン戦績・フレンド数・開拓者（最初の100人）の称号はサーバーが確かめるので、条件を満たしていないと相手には初期の称号が見えます。それ以外（CPU戦など）は自己申告です
- **唯破是律**：コンソールで `cheat.godMode()` などを呼ぶ・ゲームの中身（`SIM`）をさわろうとする・画面で godmode などと打つと付く「わな」の称号です。本物のチート対策（サーバー側の検知）とは別で、ゲームには何も影響しません
- 部屋番号は6桁のランダム。相手が10分来なければ部屋は自動で閉じます
- 物理・武器・ステージの地形・CPUの思考は `sim.js` にまとまっていて、ゲーム画面（`index.html`）とサーバー（`game.js`）が同じファイルを読みます。バランスを変えるときは `sim.js` だけを直し、GitHubに上げ直せば両方に反映されます
- `sim.js` と `lang.js`（画面の文字の辞書）は `index.html` と同じ場所（リポジトリの一番上）に置いてください。サーバーは同じフォルダか、ひとつ上のフォルダにある `sim.js` を読みます
- `gunduel.service` はラズパイなど自前のLinuxで動かす場合の自動起動設定です（Railwayでは使いません）
